# herdr-note

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md)

Herdr アプリの右側に、現在の Space とタブのメモを表示する `note` Mod です。
右上の **Files ボタンのすぐ左にある Note ボタン**で、パネルを開閉できます。

- 上段の **Space**: プロジェクト共通のメモを 1 つ、長期保存します。
- 下段の **Tab**: 選択したタブの作業メモを 1 つ表示します。タブ自体を閉じると削除されます。
- プレーンテキスト、自動保存、各セクションの折りたたみ、上下の高さとパネル全体の幅の調整に対応しています。
- パネルの開閉状態は、現在のレイアウト全体で共通です。メモの内容は現在の Space とタブに合わせて切り替わります。
- 同じタブの Agent はタブメモを共有します。Agent を切り替えたりパネルを隠したりしても、メモは削除されません。

Space・Tab の見出し横にある `−`・`+` で、それぞれのメモ本文の文字サイズを調整できます。
初期値は 13px、範囲は 10～28px で、1px ずつ変わります。見出しとボタンのサイズは変わりません。
サイズは各セクションの設定として保存され、Space やタブの切り替え後も、アプリの再起動後も維持されます。

Herdr の**デスクトップアプリ**用 Mod です。標準の `main` レイアウトと、その構造を保った
コピーを対象としています。すべてのカスタムレイアウトや OS での動作を保証するものではありません。
インストーラーは Herdr 0.1.14・0.1.15 の標準構造に対応しています。
検証範囲は [VALIDATION.md（韓国語）](VALIDATION.md) を参照してください。

## インストール

インストールには **Node 22 以上**、起動中の Herdr アプリ、PATH から実行できる
`herdr-app` CLI が必要です。インストール後の Mod の実行には、Node や npm は不要です。
追加パッケージのダウンロードや `npm install` の実行も必要ありません。

```sh
git clone https://github.com/brad36i/herdr-note.git
cd herdr-note
node scripts/install.mjs --dry-run
node scripts/install.mjs
```

`--dry-run` は変更予定を表示するだけです。実際にインストールすると、現在のレイアウトと
タブバーをそれぞれ `herdr-note`、`note-tabs` にコピーし、コピー先の Files ボタンのすぐ左に
Note ボタンを追加します。右側のメモパネルを組み込んだ新しいレイアウトに切り替わります。
元のレイアウト、タブバー、キー設定、既存のメモデータは上書きしません。

インストール先の `mods/note/mod.json` では `place: none` を指定し、元のレイアウトに
パネルが自動追加されないようにしています。同一の note ランタイムがすでにある場合は
再利用できます。内容の異なるファイルがある場合や、作成先のレイアウト名・タブバー名が
重複する場合は、上書きせずに中止します。標準構造を確認できないカスタムレイアウトも
自動では変更しません。

レイアウト名と Mod 名に使えるのは、英字・数字・`-`・`_` のみです。コピーしたタブバーと
レイアウトには、元の更新が自動で反映されません。別のコンピューターでも同じ手順で
インストールしてください。メモはコンピューター間で同期されません。

必要に応じて、次のオプションでパスやコピー先の名前を指定できます。空白を含むパスは
引用符で囲んでください。

```sh
node scripts/install.mjs --home "/path/to/herdr-app" --app "/path/to/herdr-app"
node scripts/install.mjs --layout-name my-note-layout --toolbar-name my-note-tabs
```

`--home` は Herdr のアプリホームディレクトリ、`--app` は CLI の実行ファイルのパスです。
Windows では `--app "C:\path\to\herdr-app.exe"` のように指定できます。
アプリホームは、すべての OS で次の優先順位に従って決まります。

1. `--home`
2. `HERDR_APP_HOME`
3. `XDG_CONFIG_HOME/herdr-app`
4. ユーザーのホームディレクトリ内の `.config/herdr-app`

インストール中に失敗した場合は、元のレイアウトへの復帰を試みます。新しく作成したコピーは
原因を確認できるように残します。出力されたパスを確認してから、必要に応じて削除してください。

## 保存と削除

メモは、アプリホームの `shared.json` にある `note.state` キーに**平文**で保存されます。
Mod は Herdr の保存 API を使い、ファイルを直接読み書きしません。名前ではなくマシン・
Space・タブの ID に紐づくため、名前や順序を変えてもメモは維持されます。
同じ名前のタブを新しく作っても、以前のメモは引き継がれません。

入力の変更ごとに保存状態を更新し、ディスクへの書き込みは Herdr に任せます。アプリを
正常終了し、同じタブを開き直すとメモが復元されます。OS からのログアウトやコンピューターの
終了自体では削除されません。ただし、再起動後も同じタブメモを使うには、同じタブ ID が
復元される必要があります。強制終了や電源断の直前に行った最後の変更までは保証できません。

タブメモを削除するのは、そのマシンのレイアウトが `ready` になり、タブが実際に消えたことを
確認できた場合だけです。読み込み中やオフラインという理由では削除しません。
最後のターミナルの終了によってタブ自体が消えた場合も削除の対象です。
**タブメモにはごみ箱がありません。** Mod が無効な間にタブが消えた場合は、
次回の読み込み時に一覧を確認して削除します。

Space メモは、Space を閉じても自動削除しません。閉じた Space のメモを検索・復元する
専用画面はありません。複数のコピーは同じメモを共有し、同じメモを同時編集した場合は
最後の入力が優先されます。コンピューター間の同期機能はありません。

## 元に戻す・アンインストール

Herdr のレイアウト切り替えメニューで、インストール前のレイアウトを選択してください。
たとえば、元のレイアウトが `main` なら、次のコマンドでも戻せます。

```sh
herdr-app do layout.switch '{"name":"main"}'
```

別のアプリホームを使っている場合は、インストール時と同じ `HERDR_APP_HOME` を指定してください。
PowerShell などで JSON 引数の渡し方が異なる場合は、アプリのレイアウトメニューを使えます。
インストーラーが出力した新しいレイアウト、タブバーのコピー、`mods/note` は、参照されていない
ことを確認してから削除できます。**アンインストールのために `shared.json` 全体を削除しないでください。**
ほかの Mod のデータも含まれています。

## セキュリティと検証

note ランタイムは、ネットワーク送信、シェルの実行、クリップボードの読み取り、Agent への
送信を行いません。Herdr の Mod は信頼済みコードとして動作します。ほかの Mod や同じ
アカウントのプログラムからメモを保護する保存先ではないため、パスワードや API キーの
保管には使わないでください。

インストーラーはローカルファイルを読み、新しいコピーを作成し、Herdr CLI を実行します。
ランタイムとインストーラーの変更範囲は [SECURITY.md（韓国語）](SECURITY.md)、
実施した検証と未検証の項目は [VALIDATION.md（韓国語）](VALIDATION.md) に記載しています。

GitHub Actions では、Node 22 を使って Linux・macOS・Windows でそれぞれ 36 件の
自動テストが通過しています。Linux では TypeScript checkJs、ESLint、Herdr のネイティブ検査に加え、
実際のアプリ画面でインストールと再起動を検証しました。macOS・Windows の Herdr GUI や
実際の入力メソッド、OS からのログアウト・再起動・電源断は未検証です。

```sh
npm test
npm run check
```

`npm run check` には `herdr-app` が必要です。すでにインストールされている TypeScript CLI を
使う場合は、環境変数 `NOTE_TSC` に `typescript/bin/tsc` のパスを指定します。
テストでは Node の実験的な VM module API を使うため、警告が表示されることがあります。

開発計画は [PLAN.md（韓国語）](PLAN.md)、構成の説明は [RECIPE.md（韓国語）](RECIPE.md) を参照してください。
